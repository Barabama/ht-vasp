## 2. 产物位置与目录结构

产物跟着端基走，**不是集中目录**：

```text
ht-vasp/data/endpoints/<endpoint>/dfpt-qhaflow/
├── slurm_submissions.json          # 提交台账（run_id、命令、资源）
└── runs/<run_id>/
    ├── store.json                  # jobflow JobStore，逐作业输出
    ├── <endpoint>-dfpt-qha.json        # ← 分析结果（主产物）
    ├── <endpoint>-dfpt-qha-vt.json     # ← 连续 V(T) 派生结果
    ├── 1-EOS_equilibrium_relaxation/   # VASP 原始输出（gz）
    ├── 1-DFPT_volume_1/7/ …            # 每个体积一次 DFPT
    └── …
```

**一个端基可能有多个 `runs/` 目录**（历史失败重试）。取**最新且 `ok=true`** 的那个；
`BCC-Al-Ta-2` 有 5 个，其中 1 个 `ok=false`、2 个无 JSON。

**两个集群各有一份代码副本，产物不共享：**

```
429pro:  /nfs_hdd/2025/gaominliang/ht-vasp     (NFS，从这里能直接读)
B5070:   /workspace/gaominliang/ht-vasp        (独立机器，需 paramiko/SFTP)
```

同一端基可能在两边都跑过（`FCC-Al-Al-4`），两份数值一致；取任一份即可。

## 3. 主产物：`<endpoint>-dfpt-qha.json`

`schema_version = "htvasp-dfpt-qha-analysis/v1"`

### 3.1 字段

| 字段 | 单位 | 说明 |
|---|---|---|
| `ok` | bool | **先看这个**。`false` 时只有 `error` 和 `eos`，没有热力学量 |
| `temperatures` | K | `[0, 100, …, 1000]`，11 点 |
| `volumes` | Å³/cell | 采样体积，7 个（有时 5 个，见 `rejected_volume_indices`） |
| `static_energies_eV` | eV/cell | 每个体积的静态能，`energy(sigma->0)` |
| `free_energies_eV` | eV/cell | **F(V,T)**，含零点能 |
| `gibbs_eV` | eV/cell | 每个温度下对 F 取体积极小后的 G(T) |
| `equilibrium_volume_angstrom3` | Å³/cell | 同上，V(T) |
| `eos` | dict | `E0_eV / V0_angstrom3 / B0_GPa / B0prime`（0 K BM3） |
| `n_atoms_cell` | int | **换算成 per-atom 必须用它** |
| `qha_applicability` | str | 见 §3.3 |
| `rejected_volume_indices` | list | 被剔除的体积下标（静态能量门） |
| `mesh_diagnostics` | list | 仅诊断，**不要用它做判据** |

### 3.2 单位换算（最容易错的地方）

**所有能量和体积都是 per cell，不是 per atom。**

```python
n = doc["n_atoms_cell"]                 # BCC/B2/SER_BCC: 2, FCC/L12/SER_FCC: 4, SER_HCP: 2
G_per_atom_eV = doc["gibbs_eV"] / n
V_per_atom_A3 = doc["equilibrium_volume_angstrom3"] / n
```

`n_atoms_cell` 是**原胞**原子数（B2 是 2，L1₂ 是 4），不是 DFPT 超胞的 16/32。

### 3.3 `qha_applicability` 五档

| 值 | 含义 | 建议 |
|---|---|---|
| `harmonic_QHA_applicable` | 超胞公度 q 点全部无虚频 | 直接用 |
| `finite_q_soft_mode` | 有限 q 有虚频，Γ 附近稳定 | 用，但打标记；F(V,T) 形状可能不完美 |
| `gamma_soft_mode` | Γ 点虚频 | **慎用**，V(T) 可能非单调 |
| `incommensurate_soft_mode` | 失稳波矢不在公度点上 | 慎用 |
| `numerical_unresolved` | 无法判定 | **不要用** |

判定用**精确超胞公度 q 点**（bcc 16 个、fcc 32 个），不是 k 网格最低点。
`dynamically_unstable_conditional` 为 `true` 表示这个端基的 DFPT 本身动力学不稳定。

**当前 35 个的分布**：harmonic 15、finite_q 19、gamma 1、numerical 1。

### 3.4 拟合质量自检字段

```json
"checks": {
  "max_residual_meV_per_atom": 0.6,
  "volume_monotonic_in_temperature": true,
  "all_inside_sampled_window": true,
  "all_bulk_moduli_positive": true,
  "residual_within_tolerance": true
}
```

`max_residual_meV_per_atom` 是**逐温度 BM3 拟合残差**。经验分层：

| 判定 | 残差 |
|---|---|
| harmonic | 0.3 – 2.1 |
| finite_q_soft | 2.3 – 20.6 |
| 异常 | BCC-Hf-Ti-2 45.6、BCC-Nb-Ti-2 34.2 |

**建议**：残差 > 10 meV/atom 或 `residual_within_tolerance=false` 时，
`V(T)`/`G(T)` 是拟合产物而非数据，应当拒绝或单独标记。
在 ATAT 对照里量化过：58.75 meV/atom 的残差会把相界移动 Δx≈0.033。

## 4. 派生产物：`<endpoint>-dfpt-qha-vt.json`

`schema_version = "htvasp-dfpt-qha-vt/v1"`

由 `main_dfpt_qha.py --refit-vt` 生成，**不改主产物**（`runs/` 是不可变的）。
带 `source_json` 和 `source_json_sha256` 指回主产物。

比主产物多出：逐温度 EOS 参数（`eos_parameters`）、`bulk_modulus_GPa` 逐温度、
以及 §3.4 那套 `checks`。**建议优先用这个文件**——它的 `checks` 更完整。

## 5. ⚠️ em-tdb-v2 现在读不了这些文件

实测（2026-10-23）：

```python
from emtdb_v2.qha.normalizer import normalize_qha_document
normalize_qha_document(json.load(open("...-dfpt-qha-vt.json")))
# QhaNormalizationError: QHA schema_version must be 'qha-v1' when present
```

`emtdb_v2/qha/normalizer.py:22` 写死 `QHA_SCHEMA_VERSION = "qha-v1"`，并且期望：

| em-tdb-v2 期望 | ht-vasp 实际 |
|---|---|
| `schema_version = "qha-v1"` | `htvasp-dfpt-qha-analysis/v1` 或 `…-vt/v1` |
| `gibbs_temperature` | `gibbs_eV` |
| `eV/reduced_formula_unit` | `eV per cell`（`units.gibbs_eV`） |
| `temperature_alignment` | 无此字段 |

**需要一个适配器**，这是后处理的硬阻塞。适配器的语义映射建议：

```python
gibbs_temperature = gibbs_eV / n_atoms_cell        # per atom，不是 per rfu
units = "eV/atom"
temperature_alignment = "exact"                     # 11 点严格对齐
```

注意 `reduced_formula_unit` 与 `per atom` 只在纯元素时相同（一个元素一个原子）；
化合物里 reduced formula 有 2 个原子。**按 per atom 换算并显式标注**，
不要假装是 per rfu。

适配器还应该搬运 `qha_applicability` 和 `checks`，
否则下游分不清"这条曲线是判为可用的"还是"软模条件产物"。

## 8. 版本与可复现性

- 主产物是**不可变**的：重跑会生成新的 `runs/<run_id>/`，旧的不动
- `run_id` 由 `(端基, 配方, 有效 MAGMOM, 设置)` 的指纹决定，同配置重跑复用
- 每个 run 的 VASP 输入有 `INCAR.orig`（custodian 修改前）与实际 `INCAR` 的对比
- 力常数来源（`vasprun.xml` 的 `<dynmat><hessian>` 或 DYNMAT 回退）记在 provenance
- ASR 修正前后的残差都记在 provenance

**注意**：`data/endmembers/*/*-qha.json` 是**旧流程**（`qha-v1`，有限位移，
ENCUT 400/520 混杂，含 10.6% 负频），**不要和 DFPT 结果混用**。
如果 em-tdb-v2 里已经有基于旧 `qha-v1` 的产物，需要区分来源。

## 10. 跨集群产物镜像（2026-10-25 新增）

**问题**：29 个已完成端基只在 B5070 上，429pro 本地只有 23 个。
任何本地后处理（ATAT 对照、em-tdb-v2 导入、重拟合）都只看得到一半池子。

**做法**：`scripts/mirror_remote_artifacts.py` 把每个端基的**三个文件**
拉到 `data/remote/<cluster>/`，保持 `endpoints/...` 目录结构：

```
<endpoint>/dfpt-qhaflow/runs/<run_id>/<endpoint>-dfpt-qha.json
<endpoint>/dfpt-qhaflow/runs/<run_id>/<endpoint>-dfpt-qha-vt.json
<endpoint>/dfpt-qhaflow/slurm_submissions.json
```

**不复制** `runs/<run_id>/` 下的 VASP 输出（几 GB，没有消费者读它）。
整个镜像 1.5 MB。

```bash
# 拉取（需要 paramiko + .env 里的 SERVER_B5070_*）
./.conda/bin/python scripts/mirror_remote_artifacts.py --cluster B5070
# 离线复核
./.conda/bin/python scripts/mirror_remote_artifacts.py --cluster B5070 --verify
```

**为什么这个镜像可信**：`-vt` 文件里的 `source_json_sha256` 钉住了它派生自的
分析 JSON。镜像脚本逐个核对，**哈希不符就报错退出**（不是警告）。
镜像时还顺手补齐了 B5070 上 13 个缺 `-vt` 的端基
（`main_dfpt_qha.py --batch ... --refit-vt`，在 B5070 本地跑，
因为 `refit` 要读 `source_json` 的 `n_atoms_cell`）。现在两边 29/29 都有 `-vt`。

**下游怎么用**：路径里带集群名，所以来源是显式的：

```python
roots = [Path(".../data/endpoints"),
         Path(".../data/remote/B5070/data/endpoints")]   # 后者覆盖前者
```

ATAT 的 `build_atat_control_tree.py --qha-root` 已改成可重复，
后面的 root 覆盖前面的。

**注意 `source_json` 的绝对路径**：
B5070 写的 `-vt` 里 `source_json` 是 `/workspace/gaominliang/...`，在本机不存在。
读取器（`repro-atat-phaseforge/scripts/atat_sources.py:resolve_source_json`）
会退回到"与 `-vt` 同目录的同名文件"，并用 `source_json_sha256` 验证；
两者都对不上就拒绝，**不会用猜测的原子数去拟合**。
