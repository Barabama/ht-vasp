# ISIF=8 方案科学审查（2026-10-27）

## 1. 一句话结论

**不应按现有“形状是随机噪声、ISIF=8 可消噪”的论证直接改生产代码；建议做受控重算，先固定可复现配方与SQS构型，对同一构型比较 ISIF=3/8 并对多个独立构型取样，再决定生产目标。** 若目标明确限定为立方随机相的构型平均混合焓，ISIF=8 可作为候选协议，但不是无偏的普适修正。

## 3. 决定性问题：构型特定破缺还是数值噪声

对固定原子占位构型，ISIF=3 找到的非立方局部极小若经电子/离子/应力收敛且对初始条件稳健，首先应视作**该有限构型的真实对称性破缺**，不是数值噪声。当前只有不同 SQS 构型间的对比，不能证明形状差是“实现随机量”，更不能将32 meV全归形状。对于随机合金平均焓，构型特定的弛豫能是物理构型贡献的一部分；若宏观目标是维持立方平均相，ISIF=8是在定义受限系综/受限晶格的能量，不是消除误差。需改写动机为“测算立方晶格约束下的构型平均”，并报告与自由晶格能量的差。

## 4. 原文未充分考虑的问题

首要问题是**当前方法与旧数据配方不一致**。`main_sqs.py` 的 `DEFAULT_GLOBAL_INCAR`（约104行）设 ALGO=Fast，未设置 MAGMOM；旧08-21归档为 Normal、8×1.0+8×3.0。因此“当前代码重跑复现旧归档”不成立。若不锁定同一 SQS 坐标、MAGMOM、ALGO、ENCUT、赝势、k网格，ISIF因果比较被配方混杂。`ALGO=Fast` 是否对特定金属胞不收敛不能从另一套 DFPT 记忆直接推出；需看同胞电子迭代记录。仓库记忆所指 `BCC-Ti-V` DFPT 证据应查 `/home/mcmf429/.claude/projects/-nfs-hdd-2025-gaominliang/memory/bcctiv-dfpt-needs-algo-normal.md`；其结论限定 DFPT 16-site 体系，不能自动推广到 SQS relax。

另一个决定性缺口是 16 原子 SQS 单构型的统计代表性：针对强有序化的 Al-Nb、Al-Ti，立方形状锁定可能抬高真正畸变构型能量；同时从模板 a=2.8597 Å 起步与合金/元素尺度明显不匹配，可能影响收敛路径，但现有最终几何不能证明它是主要原因。应将 Vegard 起点用于受控重算，并比较多起点收敛。

## 5. 建议方案及代价

不直接替换生产默认值。先做小型配对试验：每个选定成分固定相同构型、相同高精度电子设置和 MAGMOM，分别跑 ISIF=3 与8；另取至少多个独立 SQS 对两协议重复，报告每原子平均/散差、体积、形状、应力与静态力。ISIF=3分支使用足够ENCUT直接弛豫，或弛豫后在静态设置下继续收敛几何；所有比较使用一致端元参考。若目标定义是立方约束的混合焓，选择8；若目标是零压自由构型混合焓，保留3并做构型平均。替代 ISIF=3+ISYM 并不能可靠约束随机占位的立方宏观对称性：ISYM=0反而不施加对称约束，强行高对称需额外晶格约束/对称化协议。

重跑量与CPU秒：**UNVERIFIABLE**，缺少归档 job 的 CPU 时间汇总与拟开展的构型数；不得虚构成本。建议先从现有 OUTCAR 的 `Total CPU time used` 汇总，乘新增任务数估算。

## 6. 若仍决定赞成 ISIF=8，执行前必须同步

- 明确目标是立方约束的构型平均能量，避免称形状为噪声；保留自由胞结果作偏差量化。
- 固定/记录 SQS坐标、seed实际生效性、ALGO、MAGMOM、ENCUT、POTCAR、k点与收敛设置；与旧归档分开标识，不能声称直接复现。
- 重新校准 `EDIFFG` 对 ISIF=8 的体积收敛含义；源码判据的压力/原子数与力阈值量纲不一致，不能沿用 −0.05 并解释为力精度。
- 更新 `tests/test_sqs_workflow.py::test_relax_maker_uses_full_cell_relaxation`（当前显式断言 ISIF=3），并处理 settings fingerprint 导致旧 batch manifest 被拒问题；这是预计会挡住改动的测试/兼容性门。
- 统一纯元素参考体积与能量协议；对端点/无序合金体积和应力误差做敏感性分析。
