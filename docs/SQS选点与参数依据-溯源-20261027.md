## 1. 用户的两个问题，逐个回答

### 1.1 5 点（及现行的 3 点）拟合 L0+L1 的依据

**没有找到任何理论依据。** 分三层：

1. **`sof-ace` 完全无记录。** `git log --all -- scripts/generate_sqs_structures.py scripts/fit_l_parameters_sqs.py` 只有一个提交
   `f1c9d7b`（2026-10-03 01:31:43 `feat(sof-ace): add reproducible CALPHAD and SQS scripts`），
   commit body 实测 57 字节（标题 + 空行），无设计文档。对全 ref 全 object 穷举，
   `五点/5点/five point/0.125/0.875` 作为 H_mix 拟合成分点数**零命中**。
   脚本里只有硬编码 `COMPOSITIONS = [0.25, 0.50, 0.75]`（`scripts/generate_sqs_structures.py:40`），
   那本就是**三点**。

2. **「5 点」不是 `sof-ace` 的产物，而是 `ht-vasp` 一个已被 revert 的契约。**
   `docs/SQS混合焓数据契约-v1.md`（注意是「焓」不是「热」）由 `7f83d8d`（2026-08-19 21:49:01）加入，
   第 73-74 行写「V1 计划的生产 recipe 为 5 个点，**例如** 16-atom BCC 超胞可用
   `x_A = [0.125, 0.25, 0.50, 0.75, 0.875]`」——连数值都以「例如」呈现，不是推导集；
   第 191 行把它写成不变量「必须有 5 个成功的、不同的内部 `x_A` 才可生产拟合」；
   第 93 行 schema 注释却写 `3 <= len <= 5`（与正文自相矛盾）。
   该契约次日被 `d5698bb`（2026-08-20 13:08:45 `Revert "docs: define SQS mixing data contract"`）
   整体删除；`git cat-file -e <branch>:docs/SQS混合焓数据契约-v1.md` 在
   `feat-dfpt-qha/master/feat-sqs-mix/feat-tb2j/feat-oj/hetero` 六个分支尖端**全部 absent**，
   只能从 git 对象 `7f83d8d` 用 `git show` 取回。

3. **现行的 3 点，唯一书面理由是工程成本，不是统计或文献。**
   `docs/SQS-mixing固化进度.md` §2.4（第 112-122 行）：
   「实际生产成本评估后，当前正式 recipe 改为三个内部点 `x_A = 0.25, 0.50, 0.75`……
   原因是当前第一阶段只拟合 BCC_A2 的低阶（`L0 + L1`）模型，三个点足以支撑低阶
   smoke/生产数据，同时显著减少每个二元体系的 VASP 数量」。
   这是**成本论证**，不是理论依据。

**为什么恰好 L0+L1？** 契约把 `maximum_order: Literal[1]` 写成硬约束
（`13fb500:docs/SQS混合焓数据契约-v1.md:105`、`htvasp/model/sqs_schema.py:66`），
并规定「若残差诊断显示一阶模型不足，报告失败/警告而非自动增加阶数」。
即：**顺序是先验固定的，不是用 F 检验或显著性筛出来的。**
真正测得「L1 必要」的经验数据出现在 7 周后：
`docs/TB2J与SQS数据审计-20261025.md:217-219`「ATAT 拟合出单个 L0 = −94043 J/mol，
残差 58–72 meV/atom……加 L1 后残差降到 5.44 meV/atom」。

### 1.2 SQS 输入参数设置的依据

**没有任何一组参数的取值有记录依据。** 全部是硬编码常量；唯一写了「理由」的那条是错的。

- 晶格常数：`sof-ace` 用 `BCC_A = 3.24`（`scripts/generate_sqs_structures.py:28`），
  注释「average for Al-Nb-Ti-V system」。但该值最早出现在 `0d1fb0d`
  `scripts/verify_icet/utils/b2_builder.py` 的 `lattice_const` 默认值，其 docstring 是
  「Uses **W** as prototype for BCC structure to avoid ASE warnings」——即钨的晶格常数被当作
  ASE 占位符，**不是四元平均**。`ht-vasp` 另一条线用 `2.85971129 Å`（mp-1487 B2-AlNi，
  `htvasp/model/endmember.py:80,88` 的 `get_bcc()` 只做 `replace_species`），
  全部 `data/poscars/BCC-*.vasp` 第 3 行实测 `2.8597112899999999`。
  两者差 13%（对应超胞实测 5.71942258 Å vs 6.48 Å）。

- 超胞：两端都是 `2×2×2`（16 原子），`sof-ace` 在 `scripts/generate_sqs_structures.py:47`
  硬编码，`ht-vasp` 在 `htvasp/model/sqs.py:22-26` 的 `DEFAULT_SUPERCELLS["BCC"]=(2,2,2)`
  硬编码。**无「为何 16 而非更大」的记录**；`sof-ace` 的 CE 管线反而用 128 原子
  （`run_mc_sqs_structures.py` SUPERCELL_FACTORS=(4,4,4)），也没有解释这个不一致。

- 迭代数：`sof-ace` 用 200000（`:41`），`ht-vasp` 用 10000（`main_sqs.py:76` `SQS_ITERATIONS`）。
  20 倍差异，无记录理由。**本次实测该参数对 16 原子胞无影响**：同一 50/50 构型
  `iterations=1` 目标 4.0、`iterations=10` 起即 0.333333、`≥100` 稳定在 0.229166666667
  （见 §4 复算）。

- shell_radii / shell_weights / target_objective / prefactors / bin_width / thread_config：
  **两仓都未设置**，全部静默继承 `sqsgenerator` 默认。清空可选键后 `parse_config` 实测：
  `iterations=500000`、`seed=[None]`、`shell_radii=[[0, 2.4766, 2.8597, 4.0442, 4.9532]]`、
  `shell_weights=[{1:1.0, 2:0.5, 3:1/3, 4:1/4}]`、`target_objective` 全 0、`thread_config=[64]`。
  关联空间是**隐式**决定的，两仓都无记录。

- seed：`sof-ace` 的 `np.random.default_rng(42)`（`:52`）只用于初始装饰、管不到 SQS 优化；
  `ht-vasp` 记录 `seed_applied: False`（`htvasp/sqs/generator.py:146-149`）并给出理由
  「sqsgenerator has no documented seed configuration key」——**该理由本身是错的**（见 §7）。

## 3. 公式层面的核对

### 3.1 工作区自己引用的权威形式

`sof-ace/docs/文献调研-CEF-CALPHAD理论基础与管线设计.md`：

- 第 61-65 行，Sundman 2018 Eq.3：`ᴱG_m(x) = Σ_i Σ_{j>i} x_i x_j (L_ij + Σ_{k>j} x_k L_ijk + ...)`
- 第 67-70 行：`L_ij = Σ_ν (x_i - x_j)^ν · ^νL_ij`
- 第 73 行（**校正说明**）：srfG_M 由 site fractions 定义，而 **ᴱG_M 由常规摩尔分数 x_i 的 Redlich-Kister 级数给出**。

`sof-ace/docs/SUMMARY_PAPERS_CEF_SGTE.md:212-218`：双亚晶格 reciprocal 项
`L_{A,B:A,B} = y_A' · y_B' · y_A'' · y_B'' · Δ^0G`。
`sof-ace/docs/SUMMARY_SGTE_CEF_ALIGNMENT.md:83-90`：Hillert 1970 Eq.14，
`ΔG = °G(Aa:Dd) + °G(Bb:Cc) - °G(Aa:Cc) - °G(Bb:Dd)`（参考面非平面性）。

### 3.2 两种基的代数

设无序二元 BCC_A2 的 site fraction 就是摩尔分数 `x_A = x`。

**单亚晶格置换固溶体（Sundman Eq.3 的二元退化）：**
```text
ᴱG = x_A x_B (L0 + (x_A-x_B) L1) = x(1-x)[L0 + L1(2x-1)]
```
基函数 `f0 = x(1-x)`，`f1 = x(1-x)(2x-1)`。→ 写 `PARAMETER G(BCC_A2,A,B;0/1)`。

**双亚晶格 reciprocal 项：** `ΔG = y_A¹ y_B¹ y_A² y_B² (L0 + (y_A-y_B)L1)`。
在无序极限 `y¹=y²=x` 下退化为 `x²(1-x)²[L0+L1(2x-1)]`。
此时 `PARAMETER L(BCC,A,B:A,B;0/1)` 位于两个亚晶格都混合的槽位。

两者**差一个 `x(1-x)` 因子**，x=0.5 处数值比 4 倍（`em-tdb/docs/l_parameter_review.md:46-50` 同结论）。

### 3.3 同一个真实数据集的两基拟合（本次重算）

数据：`ht-vasp/data/endmembers/BCC-*/BCC-*-sqs.json` 六个二元、每文件 3 点，
`h_mix_J_per_mol` 逐点读取。命令见文末。单位换算 `1 meV/atom = 96.485332 J/mol`。

| Al-Nb | −88278.5 | −71049.5 | 9.31 | −395959.1 | 36.62 | 4.485 |
| Al-Ti | −160081.9 | −41762.4 | 9.96 | −726015.6 | 39.84 | 4.535 |

### 3.4 pycalphad 端到端核对（本次重算）

- 把 `PARAMETER L(BCC,A,B:A,B;0/1)=−258264.5/−372524.7`（= `sof-ace/data/calphad/out_lfit_sqs.tdb:320-321`
  的 Al-Nb 数值）代入 `Model(…,'BCC').excess_mixing_energy`，令 `y¹=y²=x`：
  得 `−2531.3 / −16141.5 / −15627.9 J/mol`（x=0.25/0.5/0.75），
  与 `x²(1-x)²[L0+L1(2x-1)]` **逐点吻合**，与 `x(1-x)[...]`（−13500/−64566/−83349）差一个因子。
  → 证实 `sof-ace` 的 TDB 确实把数据拟合进了 **reciprocal 序列**。
- 对照控制：单亚晶格 `PARAMETER G(BCC_A2,AL,NB;0/1)=10000/4000` 与
  双亚晶格 `PARAMETER L(BCC_A2,AL,NB:VA;0/1)=10000/4000`，在 pycalphad 里
  x=0.25/0.5/0.75 均给出 1500/2500/2250 J/mol = `x(1-x)[L0+L1(2x-1)]`（精确）。
  → 两种写法各自正确，只要落在**与自己匹配的槽位**上。

### 3.5 与 `ht-vasp` 自己契约的冲突

## 4. 点数：数学上需要几个

### 4.1 秩与残差自由度（本次重算）

设计矩阵列：`f0=x(1-x)`、`f1=x(1-x)(2x-1)`。

| 点集 | n | rank | dof = n−rank | cond(X'X) |
|---|---:|---:|---:|---:|
| {0.25,0.75} | 2 | 2 | **0** | 4.000 |
| {0.25,0.5,0.75} | 3 | 2 | 1 | 7.556 |
| {0.2,0.4,0.6,0.8} | 4 | 2 | 2 | 7.222 |
| {0.125,0.25,0.5,0.75,0.875} | 5 | 2 | 3 | 5.050 |
| {0.1,0.3,0.5,0.7,0.9} | 5 | 2 | 3 | 6.818 |
| {k/16, k=1..15} | 15 | 2 | 13 | 7.002 |

- **n=2 不是「欠定」而是「饱和」**：两列 `f1=f0·(2x-1)` 线性无关，秩仍 2，
  拟合唯一存在，但 dof=0 → RMSE 恒为 0、`σ̂²=0/0` 无定义，单点误差 100% 进入参数。
  只有重复成分才会降秩（现有校验已拒绝重复 x 与重复 point_id）。
- **对称点集 `(X'X)_01 = 0`**（本次实测 0.000e+00）：因为 `f1(0.5)=0` 且 `f1(0.25)=−f1(0.75)`。
  即 **x=0.5 对 L1 携带零信息**，L1 完全由 0.25/0.75 两点决定。这也解释了
  为何 32 meV/atom 的实现散差恰好出现在 x=0.5（对 L1 无害的位置）。

### 4.2 误差传播：σ = 32.07 meV/atom（本次重算）

σ 来自同一成分两次 SQS 实现之差：两份 Al-Nb JSON 的 x=0.5 静态 H_mix 为
`−249.0724` 与 `−217.0063` meV/atom（`data/endmembers/BCC-Al-Nb/BCC-Al-Nb-sqs.json` 09-04
vs `data/sqs_mixing/BCC-Al-Nb/BCC-Al-Nb-sqs-mixing.json` 08-21），差 **32.0661 meV/atom = 3093.9 J/mol**。

用 `cov = σ²(X'X)⁻¹`（LM 基，x(1-x)）：

| 点集 | SE(L0) meV/at | SE(L1) meV/at | 拟合曲线在 x=0.5 的 SE |
|---|---:|---:|---:|
| {0.25,0.75} | 120.93 | 241.86 | — |
| {0.25,0.5,0.75} | 87.99 | 241.86 | 22.00 |
| {0.125,…,0.875} | 81.00 | 182.02 | 20.25 |
| {k/16} 15 点 | 43.91 | 116.19 | — |

- 200000 次蒙特卡洛复现解析值：`sd(L0)=87.75 vs 87.99`、`sd(L1)=241.89 vs 241.86`（一致）。
- **3 点达不到 5 meV/atom**：拟合曲线在 x=0.5 的 SE 为 22.0（3 点）/ 20.3（5 点）meV/at，
  是目标的 4–4.4 倍。要达到 SE(L0)=5 meV/at，需把每点 σ 降到 1.82（3 点）/1.98（5 点）meV/at，
  即每成分约 300 个独立 SQS 实现（3 点 ≈ 925 次计算），而工作区计划只有 2 个实现。
- 注明：σ 用实现间**差**当单点误差是上界口径（若取 `σ=差/√2=22.67`，则
  SE(L0)=62.2（3 点）/57.3（5 点））。无论哪种，3 点都远达不到 5 meV/atom。

### 4.3 3 点够不够？5 点买到什么？

- **识别够**：3 点即可唯一确定 L0+L1（rank=2，dof=1），并给出一个残差诊断。
  数学上 2 个不同内点已能解 2 个未知量，3 点是最小的「可算残差」集。
- **精度不够**：在 σ≈32 meV/at 的地板下，任何 3–5 点方案都做不到 5 meV/atom。
- **5 点买到的是残差冗余度**：SE(L0) 从 87.99→81.00（−7.9%），SE(L1) 从 241.86→182.02（−24.7%），
  收益主要在 L1。但 `{0.1,0.3,0.5,0.7,0.9}` 反而给更低的 SE(L0)=78.49，说明 **0.125/0.875 并非最优 5 点**。
- **16-site 下 0.125/0.875 的合法性**：`x·16 = [2,4,8,12,14]` 全为整数，且镜像对称（2↔14, 4↔12）。
  现行三点 `x·16 = [4,8,12]` 同样精确可表示且对称。**「精确可表示」不能区分两者**，
  且工作区从未把该判据用于五点集（`cf93be6:docs/SQS混合工作流.md:23` 只对三点集写过）。
- **整个工作区没有任何真实的 5 点数据集**：六份 `BCC-*-sqs.json` 全是 3 点；
  唯一的五点集出现在 `em-tdb/tests/test_sqs_mixing.py:22`（`for n_al in (2,4,8,12,14)`，
  即 x=0.125/0.25/0.5/0.75/0.875），而它是**闭式合成的玩具数据**
  （`hmix = x(1-x)(10000 + 2000(2x-1))`，`tests/test_sqs_mixing.py:24`），天生精确符合 RK 一阶。
  所以 `em-tdb` 的「exactly five」从未在真实数据上被执行过，也从未验证过它比三点好在哪。
- **真正提高精度的杠杆是重复实现，不是加点**：`docs/TB2J与SQS数据审计-20261025.md:472-476`
  自己也得出「同一成分至少要 2 个 SQS 实现，所以 5 个点要变成 8 个点」，但至今只有 2 个实现。
