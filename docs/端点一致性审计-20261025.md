# 端基一致性审计（2026-10-25）

日期：2026-10-25
范围：51 个已完成端基（429pro 本地 23 + B5070 镜像 29，1 个两边都有）
脚本：`ht-vasp/scripts/audit_endpoint_consistency.py`
结论：**没有发现不一致。** 但审计本身挖出三件比"跑一遍看有没有错"更有用的事。


## 1. 同一晶体、两次独立计算的复现性

`SER-<El>-1` 与 `BCC-<El>-<El>-2`（或 `FCC-<El>-<El>-4`）描述的是**同一个晶体**，
只是端基目录不同。这是免费的双算检验：两次运行共用输入生成逻辑，但
flow uuid、体积弛豫、MPI 分解都是独立的。

| 对比 | ΔE (meV/atom) | ΔV (Å³/atom) | ΔB0 (GPa) |
|---|---:|---:|---:|
| SER-Cr-1 == BCC-Cr-Cr-2 | **+0.000003** | 0.000000 | −0.000 |
| SER-Nb-1 == BCC-Nb-Nb-2 | **+0.000002** | 0.000000 | +0.000 |
| SER-Ta-1 == BCC-Ta-Ta-2 | **+0.000001** | −0.000000 | +0.000 |
| SER-Al-1 == FCC-Al-Al-4 | **+0.000002** | −0.000000 | −0.000 |

**结论**：同一晶体在同一个集群、不同 flow 里，E0 复现到 **3×10⁻⁶ meV/atom**。
这个数字的意义不是"精度高"，而是**流程里没有引入任何未受控的随机性**——
体积弛豫是确定性的，对称性判定是确定性的，POTCAR/INCAR 生成是确定性的。
任何一处有随机数（比如旧的 `flow_dir` 命名依赖 uuid），这里就会看到毫 eV 级的散差。

## 2. 跨集群复现：静态层逐位相同，振动层差 0.02 meV/atom

`FCC-Al-Al-4` 在两个集群各跑一次。

| 层 | 结果 |
|---|---|
| `static_energies_eV` | **逐位相同**（7 个体积全部 `==`） |
| `gibbs_eV` | max\|ΔG\| = **0.0193 meV/atom** |
| E0 / V0 / B0 | 差 0（显示精度内） |

**为什么这个分解重要**：静态能是 SCF 收敛到同一密度泛函解的产物，
换机器、换 MPI 分解都应该逐位一致——这里确实如此，说明两个集群的
VASP 版本、POTCAR、`NCORE`/`KPAR` 路径没有偷偷影响电子结构。
振动自由能要经过力常数 → 声子 → 热占据，多一步浮点累加，
0.02 meV/atom 是合理的舍入放大，不是不一致。

这条给下游一个明确的门：**跨集群的静态层可以当同一个数用，
振动层要当作有 0.02 meV/atom 噪声的量。** 对于相界（灵敏度 ~10 kJ/mol → Δx≈0.012），
这点噪声完全淹没在 SQS 层 5–72 meV/atom 的拟合残差里。

## 3. 审计脚本自己的一个陷阱：镜像会伪装成"复现"

第一版脚本把"体积网格相同"当成"同一份文件"，于是
`FCC-Al-Al-4 [B5070 vs local]` 被判为 COPY。**判错了。**
两份文件 SHA-256 不同（`33a71d53…` vs `6e41d054…`），
`free_energies_eV` 和 `gibbs_eV` 差 1.9×10⁻⁵ eV —— 是真的两次运行。

反过来，如果镜像的正是本地的同一份文件，差异会是**精确的 0**。
所以判据必须是**文件字节**，不是数值、也不是体积网格：
体积网格来自同一个确定性 EOS 弛豫，独立运行本来就该相同。

修好后脚本对 COPY 判据有独立单测（同网格不同文件 → independent；
同字节 → COPY 且报错；真差异 → 报错）。

现在的输出：

```text
ok   SER-Cr-1 == BCC-Cr-Cr-2      dE=+0.000003 meV …  [independent]
ok   FCC-Al-Al-4 [B5070 vs local] dE=+0.000000 meV …  [independent]
---- FCC-Al-Al-4 [B5070 vs local] static/vibrational static bit-identical, max|dG|=0.0193 meV/atom
```

## 4. 纯元素晶格常数 vs 实验（3% 容差，只用来抓错结构）

| | a (Å) | 实验 (Å) | 偏差 |
|---|---:|---:|---:|
| BCC Cr | 2.8712 | 2.884 | −0.44% |
| BCC Nb | 3.3097 | 3.301 | +0.26% |
| BCC Ta | 3.3223 | 3.301 | +0.65% |
| BCC Ti（亚稳） | 3.2536 | 3.310 | −1.70% |
| BCC Zr（亚稳） | 3.5805 | 3.609 | −0.79% |
| FCC Al | 4.0394 | 4.050 | −0.26% |
| FCC Hf | 4.4814 | 4.477 | +0.10% |
| FCC Zr（亚稳） | 4.5351 | 4.611 | −1.65% |

**稳定的**四个（Cr/Nb/Ta/Al）都在 0.7% 内，符合 PBE 无磁/铁磁基态的正常表现。
Ti/Zr 的 bcc 是亚稳相，实验值是高温或合金化条件下的外推，1.7% 不算异常。

这条审计的用途不是精度，而是**抓错结构**：如果某个端基的 POSCAR
写成了另一套晶格、或者 POTCAR 挂了错元素，这里会是 5–30% 的偏差。
目前没有一个超过 2%。

## 5. EOS 极小值必须落在采样窗口内

`ht-vasp` 的 analysis JSON 有 `v0_inside_sampled_window`；
51 个端基里**没有一个**是 `false`。这一条对应"V0 是扫描停止位置的产物"
那种失败模式（`ok: true` 但数值无意义），审计把它单列成硬条件。

## 6. 顺带确认：custodian 没有改过任何科学输入

扫了 210 个已归档的 DFPT 体积目录：

| 文件 | `*.orig` 与最终版本不同的次数 |
|---|---:|
| `INCAR` | **0** |
| `POSCAR` | **0** |
| `KPOINTS` | **0** |
| `POTCAR` | **0** |

`custodian.json.gz` 里 210 份日志全部是 `corrections: []`、`unrecovered_errors: []`。
也就是说归档的这 51 个端基**没有一个靠 custodian 的自动修正才跑通**——
修正过的运行（比如 `BCC-Al-Al-2` 早期的 `TOO FEW BANDS`）没有留下产物，
不会混进结果里。这消除了"某些端基的 INCAR 被偷偷改过"这一整类疑虑。

## 7. 这些结论能支撑什么、不能支撑什么

**能支撑**：

- 端基数值本身可信（同晶体复现到 10⁻⁶ meV/atom，跨集群静态层逐位相同）；
- 归档的输入没有被自动修正污染；
- 没有一个端基的 EOS 形状可疑。

**不能支撑**：

- **不能**说明端基之间的相对位置对。51 个端基里 23 个是 `finite_q_soft_mode`，
  虚频对 F(V,T) 的影响是**系统性**的，不会在"同晶体两次运行"里暴露出来。
- **不能**说明 SQS 静态层和 QHA 层一致（前者 ENCUT 400 弛豫几何，后者 ENCUT 520）。
  这一条在 ATAT 对照里量化过：`func + 96485.33·energy` 与 ABIN 差 3.7–4.0 J/mol，
  因为 SQ2TDB 的端基拟合会吸收这个差；但 `L0` 的绝对值仍受它影响。
- **不能**替代和实验相图/文献值的比较——那是下一步的事。
